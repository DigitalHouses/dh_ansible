# Обязательные правила для людей, AI-агентов и coder-исполнителей

Прочитать `docs/engineering-principles.md`, `docs/scope.md`, `docs/architecture.md` и связанные ADR **до** изменения кода. Эти правила распространяются на все новые роли, модули, playbooks, тесты и operator workflows.

## Начать здесь: исполнение инфраструктурных задач новым AI-агентом

**ПЕРВОЕ ДЕЙСТВИЕ в каждом новом чате, где просят «запусти», «прогони E2E», «исправь развёртывание», «доведи задачу до Success» или обновить работающий медиасервер:** до ответа «нет доступа» и до записи на инфраструктуру прочитать [операторский runbook для самостоятельного запуска](docs/runbooks/media-semaphore-launch.md), затем [стандарт Semaphore](docs/standards/semaphore-task-design.md). Это обязательный путь обнаружения процедуры, а не рекомендация по желанию.

- Исторически подтверждён **прямой запуск того же pinned Ansible playbook на site runner через Remote Desktop Commander от UNIX-пользователя `semaphore`**, с защищённым root-worker. Для этого **не требуется создавать Task через Semaphore API**; такой запуск не появляется в истории UI Semaphore.
- Не делать вывод «сам не могу» только по отказу Semaphore API, отсутствию UI-инструмента, неудачной первой команде или недоступности одного SSH-аккаунта. Сначала восстановить проверенный порядок действий из runbook и текущую live-картину: online runner, процессы, checkout SHA, pinned worker release SHA, site inventory, VM/pool identity, разрешённые VM/disk actions, возможные активные worker requests. Не просить пользователя повторять уже документированный запуск.
- Разрешённые изменения выполнять **только штатным механизмом**, без обхода root-worker, SHA/nonce, site approval, SSH host-key verification или ограничений инструмента. **Если удалённый инструмент явно вернул security-deny на выполнение операции — STOP**: не пробовать ту же операцию через другую оболочку, API, ключ или повышенные права. Точно назвать заблокированную операцию и отличать это от обычной ошибки команды.
- Для устранения программных ошибок уже работающей media VM не выбирать `recreate` или `erase` без отдельного разрешения. Не выдавать старые `DEPLOYED` и `Success` за результат нового запуска; после apply нужна независимая проверка, в том числе Acceptance №81.

**Единственный источник команд, проверок и исторических evidence:** [`docs/runbooks/media-semaphore-launch.md`](docs/runbooks/media-semaphore-launch.md). Не копировать длинные команды запуска в `AGENTS.md`, README или новый скрипт: поддерживать один runbook.

## Non-negotiable

1. **Не создавать сценарий под атомарную операцию или конкретную identity.** В частности, запрещены отдельные writers/preflight/verify-скрипты для `ha_user`, `pve_user`, `torrent_user`, отдельного dataset, share или snapshot при наличии одной общей операции. Один тип ресурса — один переиспользуемый контракт; список экземпляров — только в inventory.
2. До написания нового кода искать существующую роль/модуль. Дублирующую и конкурирующую реализацию не добавлять. Исключения для аппаратного bootstrap/recovery должны быть обоснованы в PR или ADR.
3. Не добавлять зависимости от устаревших репозиториев. Архивные реализации не являются рабочим источником кода. Изменения на чужих production-узлах исключены без отдельного разрешения владельца.
4. Читать live-state перед планом, применять **только утверждённые** различия, независимо проверять postconditions. При неопределённом результате write API прекращать записи и повторять **только read-only наблюдение**.
5. Параметры сайта — в `inventories/<site>/`, не в коде роли. Один repository обслуживает весь fleet; отдельные репозитории/копии roles/playbooks по домам запрещены. Отсутствие ресурса в желаемом списке само по себе не разрешает удаление.
6. Реальные опасные операции (удаление, wipe, reset/recursive ACL, PCI/SATA, изменение сети доступа) требуют адресного разрешения, preconditions и recovery plan. `--check` не считать полноценным dry-run.
7. SSH с verified host keys для обычного Linux; поддерживаемые API и проверка TLS/идентичности для PVE, TrueNAS и appliances. Минимально необходимые права, Vault и `no_log` для секретов, никакого plaintext в Git/логах/CLI args.
8. Git commit идентифицирует конкретную версию плана и применения; CI до apply. Не утверждать `PASS` по успешному запуску команды: нужны независимые фактические postconditions и повторный запуск `changed=0`.
9. Код, имена ключей, объектов и тестов — на английском. Документация, операторские инструкции и отчёты — на русском. Не создавать лишних инфраструктурных зависимостей.
10. При признаках чрезмерной сложности, дублирования или неверного паттерна **остановить реализацию, сообщить владельцу и предложить исправление**, а не увеличивать число скриптов и проверок.
11. **Bonjour/mDNS обязателен для всех новых сетевых VM/LXC, создаваемых Ansible на любом объекте.** Каждая роль provisioning обязана включать переиспользуемый guest-network baseline и проверять публикацию уникального `<hostname>.local` самим гостем. Для Linux без штатного mDNS — `avahi-daemon` (enabled/active); для ОС со встроенным механизмом — только штатный стек, без второго daemon. Доступ UDP/5353 ограничен локальным интерфейсом/сегментом LAN; DNS-SD объявляет лишь реально доступные сервисы. Независимый verify — разрешение имени с другого устройства этой LAN в фактический IP гостя; повторный apply `changed=0`. Без успешного verify сетевой guest provisioning не принимать. Явные технические исключения — только в per-site inventory с причиной; существующие production-гости не изменять массово без отдельного audit/plan/approval. Полный контракт: `docs/standards/guest-network-mdns.md`.
12. **Все новые управляемые ZFS-пулы именовать строго `<owner>-pool`.** `owner` берётся из `site.owner_slug` в Fleet SoT, а не из `site.id` и не из названия VM/CT/объекта. Имя пула, datasets и пути не должны собираться из site slug. Уже существующие legacy-пулы не переименовывать при `keep + import`: обнаруживать и сохранять их фактические имена, GUID и данные. Любое переименование — отдельный согласованный audit → plan → apply → verify с recovery plan. При несовместимой валидации — `BLOCKED`, не обходить проверки. Стандарт: `docs/standards/storage-pool-naming.md`.

## Разрешённая область текущего этапа

Пилот bootstrap выполняется на выделенном локальном runner. Production-объекты не меняются в ходе переноса репозиториев. Любые операции с TrueNAS ACL/shares и переключение ownership требуют отдельного plan/apply и явного разрешения.


## Работа в терминале оператора

Давать один проверяемый блок за этап. Не завершать и не заменять интерактивный shell оператора; при необходимости использовать subshell. Завершать отчёт строками `DONE` и `TERMINAL STAYS OPEN`. Bash/Python допустимы по назначению, но не как замена idempotent Ansible-модулей.

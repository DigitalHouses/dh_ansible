# №80 — аудит проверок и очистка

Статус: код в PR #157 (draft), не внедрён на PVE. 03.11.2026.

## Авторизация

Два выбранных survey значения — единственное распоряжение для VM (`create/keep/recreate`) и диска (`import/erase`). Никаких повторных `approvals`, NTFS/WWN/serial/GUID, approval prompts.

## Убрано из активного пути

- Отдельный Python hardware preflight и Python VM deploy; VM lifecycle сделан Ansible.
- Python ZFS reconciler и Python-зависимый ZFS boot service; штатные ZFS tools и systemd units.
- Повторные approvals из site manifest; обязательная зависимость от legacy NFS backup_export.
- Второй site.json identity marker после подтверждения приватного репозитория и точного пути manifest.
- Повторные SSH-connect/owner-mode проверки после pinned known_hosts, при сохранении сверки SSH ключа с QGA.
- Фиксированные 2 CPU/4096 MiB и статический DHCP флаг как блокирующие проверки конфигурации другого site.
- Проверка `smartctl --version` после успешной установки пакета; повторное сопоставление ZFS GUID; дублирующая проверка app boolean flags.
- Перенесена проверка незавершённой ротации пароля на момент **после** монтирования ZFS (раньше она могла пропустить реальный marker).

## Оставлено, поскольку предотвращает ущерб или подтверждает результат

- `create` только при отсутствии VM, `keep/recreate` только при существующей **нашей** VM; защита от чужих виртуальных дисков перед `recreate`.
- SATA PCI ID/класс и отсутствие владельца среди других QEMU VM; **ровно один** физический диск за этим контроллером; проверка, что диск не системный.
- Проверка отсутствия мульти-vdev ZFS перед стиранием; `import` не выполняет `wipefs`, `sgdisk`, `zpool create/destroy`.
- Проверка реально импортированного ZFS pool на единственном SATA диске и конечного доступа/монтирования.
- Проверка QGA/SSH host key против доступного через PVE доверенного канала; конечная связь с гостем.
- Проверки фактической готовности Plex/Jellyfin/сервисов и аутентификации, если не являются дублями.

## Не считать завершённым до проверки

- Проверка всех шести сочетаний `VM × Disk`, отказов и повторного выполнения (`keep+import`).
- Испытание на реальном PVE без стирания, затем отдельный согласованный destructive E2E.
- Обновление тестов, привязанных к старым названиям/скриптам. По решению владельца **любой собственный Python, включая изменение Python-тестов, требует отдельного согласования** — старые тесты в CI пока считаются legacy и могут не соответствовать новой архитектуре. Не маскировать красные тесты.
- Удаление старых Python-файлов из всего репозитория только после проверки остальных пользователей этих файлов (исторический worker, отдельный NFS adapter).
- Замена собственных Python-скриптов *внутри приложений* — отдельный функциональный рефакторинг. Данный PR устраняет собственный Python из **инфраструктурного пути VM/ZFS**, но не переписывает Plex/Filestash/password-portal приложения.

CI PASS не приравнивается к LIVE E2E. PR не сливать до проверки работоспособности всех основных сценариев.

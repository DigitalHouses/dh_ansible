# DigitalHouses Media Server — первоначальные учётные записи

Решение владельца от 27 октября 2026: **сохраняем существующий путь `/digitalhouses/credentials`**. Переносить файлы в `/digitalhouses/users` не нужно.

На медиасервере путь ZFS: `/serzhan-home-pool/digitalhouses/credentials/`.

На первом запуске создаются пользовательские пароли и записываются как обычные TXT-файлы с логином и паролем. Повторный запуск `keep + import` не меняет уже созданные значения. Пользователь `serzhan` имеет группы `media_group` и `doc_group`; `serzhan_admin` состоит во всех назначенных прикладных группах. Для этих SMB-пользователей максимальная длина пароля — 8 символов.

Владелец забирает готовые файлы и самостоятельно отправляет их пользователям через WhatsApp. Дополнительный интерфейс и специальные механизмы выдачи паролей не нужны.

**Отдельно:** учётные данные MQTT для `digitalhouses_plex_agent` владелец разрешил записать в уже существующий зашифрованный Fleet Vault (`dh_ansible_fleet_detail/secrets/fleet.vault.yml`). Не записывать MQTT-пароль в обычный Fleet inventory `media_vm.yml`, публичный GitHub, сообщения чата или журналы.

Остальные приложения должны быть настроены автоматически и не должны на каждом запуске требовать повторного ввода пользовательских паролей. Пока код приложений ожидает подготовленные административные файлы, задача №80 не принята к запуску.

Выполнение на существующей VM: только `keep + import`; никакого удаления VM/ZFS.

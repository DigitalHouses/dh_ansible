# ADR-0022 — Задача №80: Ansible-only и независимые действия

**Статус:** принято владельцем, 03.11.2026. **Область:** инфраструктурный цикл VM и ZFS в №80. Это не разрешение на разрушительный запуск.

## Проблема

В №80 накопились отдельные Python-оркестраторы PVE preflight, VM lifecycle и ZFS, дублирующие разрешения, legacy-переходы и специальные ветки восстановления. Исправление одного режима порождало регрессию другого.

## Решение

1. **Любой собственный Python в DigitalHouses / Ansible-2 — только с отдельного предварительного согласования владельца.** Запрет распространяется на новые и изменяемые .py, helpers и custom modules. Штатный Python runtime Ansible/поддерживаемых коллекций — не собственный код. Существующие прикладные Python-службы не удалять без согласования их функциональной замены.
2. **№80 инфраструктурно переписывается на Ansible.** Штатные модули и поддерживаемые коллекции имеют приоритет. Нативные команды Proxmox и ZFS вызываются через ansible.builtin.command, если подходящего модуля нет. Собственных Python/Bash orchestration wrappers не создавать.
3. **Два независимых case, без шести отдельных реализаций.**
   - VM: keep — не создавать VM, продолжать конфигурацию существующей; create — создать отсутствующую; recreate — удалить только принадлежащую проекту VM, затем использовать тот же блок создания, что у create.
   - Диск: import — импортировать существующий ZFS без операций стирания; erase — стереть единственный физический диск выделенного PCI SATA контроллера, затем создать ZFS. Дальше общий блок datasets/медиа-сервисов.
4. **Выбор в Semaphore и есть распоряжение.** Никаких дополнительных approvals.provision/gpu_cutover/sata_cutover, проверок прежних NTFS/WWN/serial/GUID как разрешений, повторных интерактивных подтверждений.
5. **Технические границы остаются:** правильная VM, правильный PCI-контроллер, ровно один SATA-диск, исключение системного диска, проверка результата. Ошибка import никогда не запускает erase. Произвольная поломка не приводит к recreate.
6. **Никакого параллельного механизма восстановления.** Частично подготовленная VM доводится до целевого состояния теми же идемпотентными задачами Ansible.
7. **NFS legacy не блокирует №80.** PBS и backup jobs — отдельная задача. Никаких автоматических удалений старых backup jobs/storage в №80.
8. **Критерии приёмки:** шесть комбинаций действий, повторное выполнение keep+import, безопасный retry после сбоя, доказательство отсутствия wipe при import, действительное состояние VM/PCI/ZFS/сервисов. CI не заменяет live E2E.

## Переход

Черновой PR #156 был лишь частичной очисткой. Не принимать его как выполнение этого решения. Новый поток должен полностью заменить Python entry points в инфраструктурном пути №80. Существующие прикладные Python-сервисы сохраняются до отдельной оценки.

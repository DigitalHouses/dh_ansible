# ADR-0021 — Site credentials: native Semaphore OSS storage

**Статус: архитектурное решение ПРИНЯТО владельцем; реализация и E2E ещё НЕ ВЫПОЛНЕНЫ.**
Решение для новых объектов; существующие site/credentials не изменять автоматически.

## Решение

Каждый дом = собственный проект Semaphore. **Единственное рабочее хранилище
credentials объекта — штатные средства данного проекта Semaphore OSS.**
Не создавать обязательный plaintext credential store на runner, отдельный
site Vault в Git или собственный Secret Manager для текущих credentials.

- **Key Store → Local**: SSH keys, Git authentication, логины/пароли
  административного подключения, sudo/become и Ansible Vault passwords.
- **Variable Groups → Secrets**: переиспользуемые секреты приложений
  и API (MQTT, Home Assistant, Cloudflare и прочие), согласно
  поддерживаемой версии Semaphore и назначению потребляющего шаблона.
- **Secret Survey**: только одноразовая защищённая *передача значений* в задачу
  №05, не долговременное хранилище. Сохранение — через документированный
  API Key Store / Variable Groups, без вывода значений и CLI arguments.
- **Ansible Vault**: поддерживается для зашифрованных проектных данных,
  если необходимо. **Не является обязательным вторым хранилищем всех
  введённых credentials**, не должен дублировать Semaphore.

## Операторский UX

**05 · Obtain Credentials (одна задача на весь объект)**:
форма со скрытыми полями для всех используемых данным site credentials.
Администратор вводит всё необходимое **сразу**, одним запуском. Пустые
поля не стирают сохранённые значения. Изменение существующего секрета
должно быть явным, с правами администратора, по аналогии со штатным
Key Store Override. После записи проверить созданные идентификаторы и
привязки, но **не** печатать, возвращать в API-ответе или журналировать
значения секретов. Важно: заранее проверить на установленной версии
Semaphore, что все поля Secret Survey и операции API на самом деле
поддерживают этот контракт. Доступ записи в Key Store/Variable Groups
ограничить необходимыми правами, исключить общий неограниченный
административный токен в исполняемом playbook.

**06 · Check Credentials (вторая универсальная задача)**:
читает сохранённые проектные credentials штатным способом, безопасно
проверяет **весь обязательный комплект** данного объекта (не только
credentials конкретной задачи), проверяет фактическую авторизацию и
необходимые привилегии. Проверки независимы и агрегируют **все ошибки**
без остановки на первой. Результат — перечень name/target/status/reason/
next action и итог `READY` или `BLOCKED`, без раскрытия секретов.
Коды: `PASS`, `MISSING`, `AUTH_FAILED`, `INSUFFICIENT_PRIVILEGES`,
`UNREACHABLE`, `UNVERIFIED`, `MISCONFIGURED`, `NOT_APPLICABLE`.
Не считать отсутствие связи доказательством неправильного пароля.

**Каждая обычная Ansible задача** вызывает тот же общий read-only
credential check в `pre_tasks` **текущего запуска** до изменения
инфраструктуры. Все обязательные credentials должны быть исправны;
неисправный MQTT-пароль может блокировать развёртывание PVE — это
сознательная строгая site policy владельца. Никаких исключений для
сервисов, не связанных с конкретным playbook. Исключение из readiness
gate: Bootstrap, 05 Obtain, 06 Check и санкционированное recovery,
иначе исправление credentials станет невозможным.

Семафор сохраняет историю успеха/ошибок задач, но **старый SUCCESS
не является бессрочным флагом разрешения**. При каждом новом Deploy
выполняется свежий Check внутри того же Ansible запуска. Отдельный
flag store и платный Semaphore Workflow не нужны.

## Хранение, безопасность, восстановление

- Никаких secrets в коде, plaintext Git, логах, выводах диагностики,
  CLI argv, именах файлов и обычных Ansible facts; `no_log` на операциях
  с секретами, отдельно сформированный безопасный отчёт.
- Доступ к №05 только администратору проекта; для остальных задач
  минимально необходимые права, привязки credentials к проекту.
- Защищённая резервная копия **базы Semaphore + отдельно защищённая
  копия `access_key_encryption`** и проверенное восстановление.
  Потеря ключа делает сохранённые в БД secrets непригодными.
- До удаления старого CT и миграции №05/06 провести на `serzhan-lab`
  контрактный тест supported API и роли, тест двух неверных credentials,
  reboot и восстановление из резервной копии. Не переносить автоматически
  credentials других объектов.

## Migration / supersedes

Этот ADR **заменяет целевую схему** обязательного
`site_vault_v1` из раннего прототипа (2026-11-01). Пока в коде остаются
прежние №05 GitHub, №06 Fleet Vault, `fleet_credentials`, а новый
Bootstrap создаёт `site_vault_v1`; эти части **не отвечают ADR**.
Не заявлять, что система внедрена, пока весь путь 05 → 06 → обычная
задача не принят E2E. Старую функциональность сохранять до проверенного
перевода, не удалять credentials без резервной копии.
